# Similarity-list reverse engineering, 2026-10-19

Initial investigation: these are direct read-only calculation requests, authorized
by the user's instruction to begin reverse engineering. Thirteen bounded POSTs
were sent: three baseline, nine development controls and one production control. Each JSON record preserves URL, timestamp, exact request,
status, media, diagnostic ID and decoded response. No retries were used.

The archived frontend sends `_chemicals`, not `get_chemicals`, and explicitly
sets `fingerprintName=indigo` and `scoreName=tanimoto`. It sends no separate
`chemicals` field. The full request returns one atrazine row against bisphenol A
in both production and development, with similarity 0.138. Staging returned 502;
its calculation remains unverified. Two algorithm fields plus main/_chemicals
reproduce the production result without the unrelated RDKit/PaDEL controls.

Development controls establish:

- Omitting fingerprintName yields 400 naming fingerprintName.
- Supplying fingerprintName but omitting scoreName yields 400 naming scoreName.
- Replacing `_chemicals` with schema-declared `get_chemicals`, while keeping
  all scoring settings, yields 400 requiring `_chemicals`.
- The reference chemical is excluded: self-only returns [], other-only returns
  atrazine, and reversing the reference returns bisphenol A with the same score.
- Minimal chemId/sid/smiles objects work. SMILES-only objects also work for these
  two inputs, with service-generated chemId values equal to their SMILES.

The old empty-array controls omitted scoring settings and self-only is not a
valid positive-result control. Prior evidence did not justify declaring the
service unusable. The legacy public wrapper was incorrect: it nested extra options,
used resolved ChemicalRecord envelopes and did not map `_chemicals` correctly.

Fresh schemas from all three environments continue to declare get_chemicals,
not _chemicals, and lack required markers/defaults for scoring fields. They live
in the parent directory. Canonical schema archives remain unchanged.

Reproduce baseline: `python3 dev/specmill-rebuild/issue-358/similarity-investigation/probe.py`

Reproduce controls: same command with `--suite controls`.

Verify saved evidence offline: `python3 dev/specmill-rebuild/issue-358/similarity-investigation/verify.py`

The base wrapper is now generated by Specmill 0.1.51 from the reviewed schema
recorded in ../similarity-provenance.json. It accepts main as one identifier,
query as candidate identifiers, and explicit Indigo/Tanimoto defaults. Two
pre-hooks resolve the reference and candidates independently. get_chemicals
is removed from the public interface. Positional callers must be updated.
No generator capability gap has been demonstrated.

The isolated installed package passed four live wrapper calls in development
and production: two nonempty comparisons and two self-only comparisons.
installed-wrapper-live.json preserves their results. live-wrapper.R reproduces
the calls given an installed library path. No localhost server was used.
Hook/policy/resolver tests passed 662 assertions without warnings or skips.
Other algorithms, larger inputs, ordering/ties, duplicates, invalid structures
and full production/development error parity have not been characterized.
